PACKAGES (packages/)
  kirkwood-generic/  target packages and kmods; base/ luci/ packages/
  routing/ telephony/ video/  the feeds; each folder has packages.adb.
  The kmods only fit this kernel (kernel-6.12.112~bd9feb10...). The ones
  from downloads.openwrt.org have another hash and do not install, so
  take kmods from here. Normal userspace packages can come from the
  official feeds as well.
  The indexes are signed with the build key; public-key.pem here is the
  same key the image ships in /etc/apk/keys/, so no --allow-untrusted.
  Use: put the folder on a USB stick or web server, and add lines to
  /etc/apk/repositories.d/customfeeds.list, e.g.
    file:///mnt/sda1/packages/kirkwood-generic/packages.adb
    http://192.168.1.2:PORT/packages/base/packages.adb
  then apk update && apk add <pkg>.

SOCKET LEDs AND LINK (found 2026-10-30, all in the DTS reg-init)
- Each socket LED is driven by the switch PHY (88E1121R core), page 3 reg 16:
  LED[0] = right LED green, LED[1] = right LED orange, LED[2] = not wired,
  LED[3] = LEFT LED. The PHY reset default 0x1777 is right: green on at
  1000 Mbit, orange on at 100 Mbit, left LED on with link and blinking with
  activity. The marvell driver writes 0x0030, so the DTS writes 0x1777 back.
- Wiring checked by forcing outputs (2026-10-31, mode 9 = on, 8 = off): the
  right LED is a two-pin bicolor between LED[0] and LED[1] (both on = dark),
  the left LED is green only, on LED[3]; LED[2] lights nothing. There is no
  orange for the left LED.
- WAN socket: LED[0] (green) is not wired, only orange. With 0x1777 the
  right LED stayed dark at 1000 Mbit. The stock LaCie kernel writes the same
  0x1777 (switch code, page 3 reg 16; variant with reg 17 = 0x44aa tested,
  no green either), so it was never green there. WAN uses 0x1767:
  LED[1] mode 6 = right LED orange with link (tested at 1000 and 100 Mbit;
  10 Mbit untested, the far end has no 10 Mbit).
  LED[1] modes on this PHY: 0/5 off, 1/2 link+activity, 3/4 activity only,
  6 link at 100/1000, 7 link below 1000.
- Do not write page 3 reg 18 (0x4105): writing 0x4100 there dropped the
  wan link for ~12 s.
- Energy-detect power-down (page 0 reg 16 bits 9:8, on by default) breaks the
  link to a "green" switch: preinit drops the port at ~15 s, both ends go to
  sleep, and netifd at ~35 s never gets a link back (only a cable replug
  helped). The DTS clears the bits and soft-resets the PHY:
    marvell,reg-init = <0 0x10 0xfcff 0>, <3 0x10 0 0x1777>,
                       <0 0x00 0xffff 0x8000>;
- Diagnostics in the image: ethtool-full, mdio-tools (kmod-mdio-netlink).
  PHY bus: mdio '!ocp@f1000000!mdio-bus@72004!switch@a!mdio' phy N raw REG
- LuCI: no swconfig "Switch" page with DSA. Ports and VLANs are under
  Network > Interfaces > Devices > br-lan > Configure > "Bridge VLAN
  filtering"; port status is on Status > Overview (Port status).

FLASH / RECOVER
1. Normal update (OpenWrt running):
     sysupgrade -v /tmp/openwrt-...-squashfs-sysupgrade.bin
2. OpenWrt broken, U-Boot fine: boot menu "Web recovery" (or rear button),
   browse http://192.168.1.1/ and upload the factory.bin; or "Flash
   firmware from TFTP server" (TFTP root of 192.168.1.2 must hold
   openwrt-kirkwood-generic-lacie_wireless-space-squashfs-factory.bin;
   "Boot initramfs from TFTP" loads the ...-initramfs-uImage the same way).
3. U-Boot broken: UART boot with the patched kwboot (power-cycle the box,
   kwboot catches the BootROM only on a real power-on, 15-20 s off):
     kwboot -t -b u-boot-2026.10-wireless-space.kwb /dev/ttyUSBx
   then rewrite block 0 from that RAM U-Boot:
     nand erase 0x0 0x100000
     tftpboot 0x2000000 u-boot-2026.10-wireless-space-rs-ecc.raw
     nand write.raw 0x2000000 0x0 0x14c     <- page count is HEX (332)
   The BootROM reads block 0 only with the Marvell 4-bit RS ECC (10 bytes
   per 512 B in OOB 24-63), which neither mainline U-Boot nor Linux write;
   hence the pre-encoded .raw (kwrs.py encode u-boot.kwb out.raw).
4. Back to stock LaCie: kwboot as in 3, then nand write.raw the stock dumps
   (mtd0 + mtd1 here, mtd2 from the full backup), page-exact with OOB.
